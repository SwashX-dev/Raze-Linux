# r6 — init and service supervision

r6 is a Rust init and supervision suite inspired by s6. Since Raze 1.1 it is the
**default PID 1 and service manager** of every Raze system: the live ISO, installed
systems and the default Rift desktop. It is covered by unit tests and end-to-end
tests that run the real binaries (`cargo test -p r6`).

## Binaries

| Binary | Role |
|---|---|
| `r6-init` | PID 1: mounts `/proc`, `/sys`, `/dev`, `/dev/pts`, `/dev/shm`, `/run`, cgroup2; runs `/etc/r6/rc.init`; starts and respawns `r6-supervise`; reaps orphans; drives shutdown (stop services → `rc.shutdown` → SIGTERM/SIGKILL all → unmount → `reboot(2)`). Panics are caught; PID 1 never exits. Emergency shell after repeated supervisor failures or with `r6.emergency` on the kernel command line. |
| `r6-supervise` | Supervises **all** services from one event loop (poll + signalfd). |
| `r6-activate` | Validates a service directory (unknown deps, cycles) and prints the parallel start plan. Used at system build time. |
| `r6-log` | Size-rotated, timestamped log writer (stdin filter; same code the supervisor uses). |
| `r6` | Control CLI (also installed as `poweroff`, `reboot`, `halt`, `shutdown`). |
| `r6-user` | Per-user supervisor for session services (`~/.config/r6/services` over `/etc/r6/user-services`); started by `raze-session`, stopped at logout. |
| `r6-tmpfiles` | tmpfiles.d implementation (types f F w d D e v q Q p L c b C x X r R z Z, modifiers `+ ! - ?`). |
| `r6-config` | Inspect the service configuration: `check`, `show`, `graph` (dot), `dirs`. |
| `r6-syslogd` | Receives syslog(3) messages on `/dev/log` (`r6 logs syslog`). |

## Design difference from s6

s6 runs one `s6-supervise` process per service, plus one `s6-log` per logged
service, coordinated by `s6-svscan` (and `s6-rc` for dependencies). r6 runs one
supervisor process for everything: service output pipes, readiness pipes and the
control socket are multiplexed in a single poll loop. Dependency ordering is a
local decision of that loop rather than an IPC protocol.

Measured consequence (Raze Core, 23 services, see
[benchmarks](../performance/benchmarks.md)): 2 processes instead of 27, about half
the summed RSS, the same activation latency — but higher PSS than s6, whose many
small processes share pages. r6 is not "faster than s6"; it is equally fast with a
different process model.

## Service definitions

`/etc/r6/services/<name>.toml`:

```toml
description = "DHCP client"
command = ["/bin/udhcpc", "-f", "-i", "eth0"]   # absolute path required
type = "longrun"            # or "oneshot" (ready when it exits 0)
depends = ["udev"]          # hard: started first; failure propagates
wants = ["syslog"]          # soft: ordered first if present; failure ignored
ready = "notify"            # "immediate" (default) or "notify": write "\n" to $R6_NOTIFY_FD
ready_timeout_ms = 30000
restart = "on-failure"      # "always" | "on-failure" | "never"
restart_delay_ms = 250      # doubled per recent restart, capped at 30 s
restart_max = 5             # within restart_window_s; then the service is "failed"
restart_window_s = 60
stop_signal = "TERM"        # sent to the service's process group
stop_timeout_ms = 5000      # then SIGKILL
user = "nobody"             # optional; supplementary groups are set
group = "nogroup"
capabilities = ["CAP_NET_BIND_SERVICE"]  # ambient capabilities kept after dropping to `user`
umask = "0077"
rlimit_nofile = 1048576
oom_score_adjust = -900
runtime_directory = "name"  # /run/name (or $XDG_RUNTIME_DIR/name), owned by `user`
state_directory = "name"    # /var/lib/name
environment = { KEY = "value" }
log = "file"                # "file" (default) | "console" | "null"
enable = true               # start at boot
```

Unknown keys, relative commands, self-dependencies and cycles are rejected. A
reload with an invalid configuration keeps the running configuration.

## Supervision semantics

- **Activation**: a wanted service starts as soon as all its ordering
  dependencies are `up` (or `done` for oneshots); independent services start
  concurrently. 50 services taking 300 ms each to become ready activate in well
  under a second (test `many_services_start_concurrently`).
- **Readiness**: `immediate`, or s6-style notification on a pipe at fd 3.
- **Restarts**: exponential backoff; more than `restart_max` restarts within the
  window marks the service `failed` (no restart storms). `r6 start` clears it.
- **Stopping**: dependents are stopped first; SIGKILL after the stop timeout.
- **Supervisor crash**: `r6-init` respawns the supervisor with backoff. Service
  PIDs and start times are recorded in `/run/r6/pids`; the new supervisor stops
  any surviving instance (matched by PID *and* start time, so PID reuse cannot
  hit an unrelated process) before starting fresh ones.
- **Logging**: per-service rotated logs (`/run/r6/log/<svc>/current`, or
  `/var/log/r6` when configured), lines prefixed with seconds since boot.
- **Enable/disable** persist as overrides in `/var/lib/r6/{enabled,disabled}/`,
  so declaratively generated `/etc` stays read-only.
- **Shutdown**: signals map as SIGUSR1/SIGPWR → poweroff, SIGUSR2 → halt,
  SIGTERM/SIGINT → reboot. When not PID 1, r6-init is a child subreaper and
  exits instead of rebooting (used by the tests).

## CLI

```
r6 status [SERVICE]       r6 start|stop|restart SERVICE...   (waits; --no-block)
r6 list                   r6 enable|disable SERVICE [--now]
r6 logs SERVICE [-n N] [-f]
r6 reload | check | info  r6 reboot | poweroff | halt
```

`r6 info` reports supervisor RSS and boot timing (kernel → r6-init → supervisor →
all boot services settled), measured with `CLOCK_BOOTTIME`.

## r6 on Raze systems (1.1)

NixOS's systemd-based stage 1 mounts the root filesystem and runs NixOS activation
inside the initramfs (this nixpkgs has no scripted stage 1, so systemd runs there,
and only there). At switch-root, PID 1 goes to `r6-init` on the real root instead of
systemd; `r6-init` stops anything the initramfs left behind (journald, systemctl)
and removes `/run/systemd/system`, so programs do not mistake the system for a
systemd one. Everything after that is an r6 service declared in Nix
(`raze.r6.services`, `distro/modules/r6.nix`) and validated at build time.

| systemd component | r6 system |
|---|---|
| systemd (PID 1, services) | `r6-init` + `r6-supervise` |
| systemd user instance | `r6-user` |
| systemd-journald | per-service logs in `/var/log/r6/<service>` (`r6 logs`), `r6-syslogd` for `/dev/log` |
| systemd-tmpfiles | `r6-tmpfiles` |
| systemd-udevd | eudev |
| systemd-logind | elogind (PAM, seats, suspend/poweroff for users via polkit) |
| dbus-broker | dbus-daemon |
| systemd-timesyncd | ntpd-rs (as an unprivileged user with `CAP_SYS_TIME`) |
| systemd-boot | GRUB (installer default, BIOS and EFI) |
| switch-to-configuration (systemd) | r6's own: boot loader, activation script, `r6 reload`, restart of changed services |

`nixos-rebuild switch` and `rix system switch` work: changed services are restarted,
new ones started, removed ones stopped; services whose restart would end the
running session (dbus, elogind, greetd, udevd) get their new definition at the next
boot. `raze.init = "systemd"` keeps stock NixOS behaviour.

**What remains of systemd:** systemd runs inside the initramfs (stage 1) only.
Several nixpkgs packages still link `libsystemd`/`libudev` from systemd's libraries
(for example linux-pam); Raze's own components (r6, Rift) do not.

Raze Core (`nix build .#core-image`, kernel + 3.4 MB initramfs with r6-init as
PID 1) is still booted by CI.

## Bugs found by measuring

- `kill(-1, 0)` succeeds for kernel threads, so the final shutdown wait always
  ran its full 3 s timeout. r6-init now scans `/proc` for userspace processes
  (skipping `PF_KTHREAD`): poweroff 3.2 s → 0.2 s.
- Per-service console messages during boot were the largest boot cost (serial
  console writes are synchronous). They now require `r6.verbose`: PID 1 → all
  services started ≈45 ms (3 boots) → 32.3 ms (median of 10).
